# Tasks 1.1--1.9, 2.1--2.5, partial 4.1, and 4.2 review draft

This is a minimal IEEEtran scaffold for reviewing the research questions and
claim boundaries, industrial requirement sample, and architectural pattern
catalog, applicability/RAG/ADR protocols, expert preparation and analysis plan,
and ethics, data governance and reproducibility procedures.
Task 2.2 adds the first computational Results subsection.
It is not the full manuscript.
Later sections, further bibliography
entries, result macros, and final metadata
configuration have not been implemented.

## Build

From this directory, run:

```sh
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

The build requires a local TeX installation with IEEEtran and latexmk. The
configuration writes the review PDF to `main.pdf` in this project-root
`latex-code/` directory, along with ignored intermediate build files.
The LaTeX build needs no external datasets, API access, or data processing.

## Review scope

- [Methodology fragment](sections/03-methodology.tex): protocol scope,
  questionnaire constructs, interpretation limits, and the claim-to-evidence
  matrix in source comments.
- [Research-question table](tables/research-questions.tex): question wording,
  units, evidence, and intended analysis.
- [Dataset table](tables/dataset-summary.tex) and
  [sample values](data/study-values.tex): generated from the validated source.
  Regeneration and verification are documented in
  [the processing README](../processing/README.md); the LaTeX build itself
  does not need the research data or processing scripts.
- The catalog subsection uses [central study counts](data/study-values.tex)
  and [catalog field-inventory values](data/catalog-values.tex)
  and [source citations](bibliography/references.bib). Catalog and public-source
  verification commands are documented in the processing README.
- The applicability subsection describes the strict response schema, grounding
  rules, sequential execution, retries, resume validation, and pilot exclusion.
  [Protocol values](data/applicability-values.tex) are generated by an offline
  audit; the full prompt/schema and source hashes are retained in
  [the protocol audit](../processing/outputs/applicability-protocol-audit.json).
- The RAG subsection separates vector Top-15 from reranked Top-5, documents
  query/corpus differences, and defines positive-set overlap in Equation (1).
  [RAG values](data/rag-values.tex) and the
  [frozen-input audit](../processing/outputs/rag-protocol-audit.json) are produced
  offline; no retrieval models are run or overlap findings reported in Task 1.5.
- The ADR subsection documents the Nygard-inspired prompt, synthetic example,
  fixed Proposed status, structural validation, immutable provenance, included
  pilot, and authorized technical retry. [ADR values](data/adr-values.tex) and
  [audit](../processing/outputs/adr-protocol-audit.json) are generated offline.
- [Pipeline figure source](figures/approach-overview.tex) and
  [PDF](figures/approach-overview.pdf) show the expert-results stage as pending.
  Rebuild the standalone figure after changing it, then rebuild the manuscript:

  ```sh
  cd figures
  latexmk -pdf -interaction=nonstopmode -halt-on-error approach-overview.tex
  cd ..
  latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
  ```
